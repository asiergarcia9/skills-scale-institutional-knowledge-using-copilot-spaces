# OctoAcme Project Management Overview

## Purpose
Provide a concise, shareable introduction to how OctoAcme runs projects so new teammates can quickly understand our approach, roles, and key artifacts.

## Scope
Applies to all cross-functional projects that deliver product features, services, or integrations.

## Principles
- Customer-first: prioritize customer value and usability.
- Iterative delivery: deliver small, testable increments.
- Clear ownership: each project has a named Project Manager (PM) and Product Lead.
- Data-informed decisions: measure impact and iterate based on evidence.
- Psychological safety: encourage feedback and learning.
- Cross-functional collaboration: engage all relevant personas early and throughout the project.

## Core Roles

For comprehensive persona definitions, responsibilities, and interaction patterns, see [OctoAcme Roles and Personas](octoacme-roles-and-personas.md).

### Primary Roles
- **Project Manager (PM)**: Coordinates delivery, schedules, risk, communications, and stakeholder engagement.
- **Product Manager (PdM)**: Defines outcomes, prioritizes backlog, and measures success.
- **Developers**: Implement features, collaborate on design and testability.

### Supporting Roles (Engage as Needed)
- **QA Engineer**: Design and execute test strategies; ensure quality gates before release.
- **UX Designer**: Lead user research, design, and usability validation.
- **DevOps Engineer**: Maintain infrastructure, automate pipelines, and enable reliable deployment.
- **Security Lead**: Assess security risks, coordinate reviews, and ensure incident readiness.
- **Customer Success Manager**: Ensure customer adoption and feed back customer insights.

## Key Artifacts
- Project Charter / One-pager
- Roadmap and Release Plan
- Sprint/Iteration Backlog
- Acceptance Criteria & Definition of Done
- Risk Register
- Retrospective notes and action items
- Stakeholder Engagement Plan (see [OctoAcme Stakeholder Engagement Checklist](octoacme-stakeholder-engagement-checklist.md))

## Lifecycle (high-level)
1. **Initiation**: problem statement, stakeholders, high-level timeline.
2. **Planning**: scope, resources, milestones, dependencies, stakeholder engagement plan.
3. **Execution**: build, test, review, iterate with cross-functional engagement.
4. **Release**: deploy, verify, announce, gather customer and team feedback.
5. **Close & Retrospective**: capture learnings and next steps; feed improvements back into process.

## Communication Cadence
- **Daily**: Standups with developers and delivery team
- **Weekly**: PM + PdM sync; stakeholder engagement touchpoints (see Stakeholder Engagement Checklist)
- **Bi-weekly / Monthly**: Stakeholder updates, roadmap reviews
- **Ad-hoc**: Escalations, incident response, risk management

## How to use these docs
- Keep the Project Charter updated in the project repo.
- Use the [OctoAcme Roles and Personas](octoacme-roles-and-personas.md) guide to identify and engage relevant team members.
- Reference the [OctoAcme Stakeholder Engagement Checklist](octoacme-stakeholder-engagement-checklist.md) during project planning to ensure all personas are engaged at the right time.
- Add process-specific docs into `docs/` as living documentation that evolves with team learnings.
